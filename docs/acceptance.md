## 压测客户端与“0 失败请求”的口径

数据面热升级时，旧 worker 优雅退出，会关闭空闲的 keep-alive 连接。如果客户端恰好在这一刻发出下一个请求，这个请求在线路上会失败。这是 HTTP/1.1 keep-alive 的固有竞争。

对这种情况，标准 HTTP 客户端（浏览器、Go、curl 等）会对幂等请求自动重试一次（RFC 9112 9.3.1）。

验收按“客户端看到的结果”判定，门槛由 `cmd/etos-loadgen` 给出。它使用 Go 标准库客户端，只用于测试，不随产品分发。

同时运行的 wrk 不重试，它的原始计数只作为参考写进报告。实测 50 节点升级中：
- wrk 每台约 59 万请求里有 0–7 次这样的读错误；
- 不升级的对照组为 0；
- etos-loadgen 为 0。
