## 使用范围与结果口径

本清单以 [MVP 演示手册](../demo/README.md) 的流程 1–7、[端到端脚本](../demo/e2e.sh)、[现有量化验收对照](acceptance.md) 为基线，补充当前已实现功能。未找到单独保存且带逐项执行结果的历史 MVP 签字清单，因此第一组保留为“MVP 基线回归”，不据文档描述补写历史通过记录。

这是测试设计文档，不是本轮全量测试报告。所有用例初始状态均为“待执行”；章节列出的代码、脚本和工作流表示已有相关测试入口，不表示该节每一行都已有自动化覆盖或当前镜像已经通过。本次镜像构建与冒烟证据单列在后面。

执行状态统一填写：待执行 / 通过 / 失败 / 阻塞 / 不适用。判“通过”须保留日志或截图、环境、操作者和日期；不适用须说明理由。P0 是发布阻断项，P1 是核心功能项，P2 是扩展或长稳项；每行优先级按所属模块与发布范围调整，以下默认 P1，安全、数据丢失、服务中断及应急路径为 P0。

## 发布判定

P0 问题必须清零；范围内 P1 用例通过且失败项闭环；未执行/阻塞/不适用须逐项列明，不计作通过。涉及条件门禁必须同时核对 UI 与直接 API；涉及热升级必须用真实 syapp 和业务流量；涉及应急操作必须覆盖过期/无效授权下的行为。发布报告应附测试环境、固定制品摘要、通过/失败/阻塞数量及已知限制。
