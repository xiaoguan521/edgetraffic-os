# 现有配置的观察接入与 Lua 兼容

当节点已经用独立配置运行，尤其是配置中包含原生 Lua 指令、第三方 Lua 库或本机静态目录时，先把节点加入控制台并不等于可以立即由控制台接管。使用节点组的“配置接管方式”保护现网：

| 模式 | 节点上线行为 | 控制台能力 | 适用场景 |
| --- | --- | --- | --- |
| 控制台托管 `managed` | 自动对齐节点组当前版本 | 预览、审批、发布和回滚 | 已完成迁移的站点 |
| 观察接入 `observe` | 不自动下发配置 | 上传分析、草稿、审计和漂移查看 | 先盘点现网，验证导入结果 |
| 兼容配置 `legacy` | 首次审批发布成功前不自动对齐；之后可对齐已批准版本 | 原生配置包的双管理员审批、版本管理及回退申请 | 保留原生 Lua 及第三方依赖 |

## 推荐接入流程

1. 在控制台新建或选择节点组，先在“节点组设置 → 配置接管方式”选择“观察接入”或“兼容配置”。同一台服务器的多个实例应分别使用对应的节点组；实例档案仍负责根目录、端口、共享/独立数据面和标准版/国密版匹配。
2. 在节点上执行控制台的“已有实例注册命令”。`-replace-local-config` 检测到当前版本目录的改动时会把该目录打包到 Agent 状态目录的 `backups/standalone-*.tar.gz`；它不能保证包含另一个 `-c` 指定的主配置、目录外的 include、证书和 Lua 依赖。请先按下文备份实际使用的完整文件。
3. 在“配置导入”中上传完整配置展开结果、保留目录结构的 `tar.gz`，或一次选择主配置和它引用的多个文件。导入器只读取上传内容，不会让控制台通过 Agent 任意读取节点文件。
4. 先查看导入报告和重新校验结果。报告会列出未转换指令、缺失的 include、证书材料、站点路由以及 Lua 兼容清单；其中按文件名猜测的 Lua 路径和静态扫描出的 `require` / `dofile` 依赖均需人工核对。控制台不会执行导入内容。
5. 选择后续方式：保留原生 Lua 时在“兼容配置”模式提交完整配置包；完成转换为站点草稿时可切回“控制台托管”并显式发布。切换后节点重连不会自动对齐，直到完成首次显式发布。发布预览只比较控制台草稿和控制台保存的版本，不能代替对节点原始配置的人工核对。

## 备份实际配置和外部依赖

在节点本机确认数据面启动时的 `-c` 主配置，并将它以及主配置引用的目录、证书、Lua 脚本和第三方库全部列入备份。以下路径只是示例，按实际环境调整：

```bash
sudo syedge-agent backup-config \
  --config /home/atwasoft/node/conf/current/syedge.conf \
  --source /home/atwasoft/node/conf \
  --source /home/atwasoft/openresty/nginx/conf \
  --source /home/atwasoft/openresty/nginx/lua \
  --source /home/atwasoft/openresty/nginx/zs \
  --output /root/syedge-config-backup.tar.gz

sudo tar -tzf /root/syedge-config-backup.tar.gz
```

命令不会自动推断所有动态引用；必须由运维确认 `--source` 覆盖完整依赖。软链接会保留，若目标不在所选源中则拒绝备份并提示补充。归档包含原路径对应的 `rootfs/` 目录及源清单，可能包含私钥和凭据，文件权限为 0600；恢复时应先解压到独立目录核对，避免直接覆盖现网。

## Lua 的边界

控制台托管的 Lua 仍然是 `docs/lua.md` 定义的受限路由脚本：脚本经过双人审批，写入不可变版本，并只能使用批准的运行时能力。`dofile`、任意第三方 `require`、文件读写、数据库直连和 `ngx.socket` 等旧配置依赖不会因为导入而自动获得权限。

导入报告检测到 `*_by_lua_file`、Lua 动态模块、`lua_package_path` 等内容时，会标记需要兼容处理，并列出上传包中发现的 Lua/依赖文件。需要迁移到受限站点配置的功能，应逐条改写并在测试节点上验证。原生兼容包中的代码不受受限 Lua 沙箱约束，节点上的文件、网络及操作系统权限取决于数据面进程；旧系统的 master 可能以 root 执行。

## 提交和审批原生兼容包

1. 先备份实际运行的主配置、所有 include、证书、Lua 脚本和外部依赖。在测试节点验证配置、脚本和业务请求。所有目标节点的服务必须显式使用 `-c` 指向对应实例的 `conf/current/syedge.conf`，并使用正确的 `-p` 前缀。Agent 在切换前核对正在运行的 master；无法核对或指向其他路径时拒绝发布。仅在其他 `-c` 路径运行的进程不会因切换 `current` 自动改用新配置。调整启动路径可能需要维护窗口。
2. 为每个目标实例升级到支持原生兼容包的 Agent，并安装相匹配的 SyEdge、Lua 附加包以及配置需要的第三方库。旧 Agent 不会上报所需安全能力，控制台会拒绝向其下发兼容包。标准版/国密版、CPU 架构与动态模块 ABI 必须匹配；附加包不自动提供任意 OpenResty 第三方库或系统依赖。
3. 准备一个独立目录，根目录放 `syedge.conf`，按需放入 `conf.d/`、`lua/`、证书等普通文件。例如将旧配置内需要随版本变更的路径改为 `@SYEDGE_RELEASE@/lua/init.lua`；该标记只在 `.conf` 和 `.lua` 文件中替换为节点组实例的实际版本目录。相对路径仍由数据面 `-p` 前缀解析，绝对路径仍指向节点本地，二者都不会自动改写或自动收集。引用包外文件时需确保各节点均已部署并有权限访问。
4. 在准备目录中执行 `tar -czf /tmp/syedge-legacy.tar.gz .`。归档必须是 tar.gz，不支持软链接和特殊文件；压缩后不超过 20 MiB、解压内容不超过 48 MiB、文件不超过 4000 个。版本内文件以 `0640` 部署，依赖执行权限的辅助程序应预先安装在节点上。不要包含不需要的密钥或业务数据。
5. 拥有 Lua 功能授权的管理员在发布页上传包并提交。按需配置本机 HTTP/HTTPS 探活（使用节点组档案中的端口）；未配置探活时，只检查配置加载，不能证明业务请求正常。另一位管理员下载冻结包，核对脚本、依赖、路径与敏感信息，审批后才下发。下载包含敏感信息，应妥善保管并及时删除副本。
6. 控制台加密保存兼容包，并审计提交、下载和审批；需安全备份控制台数据目录的 `secret.key`，否则无法解密历史包。版本回退需再次由两位管理员提交和审批，并按批准摘要验证节点本地文件。节点离线或未持有历史批准摘要时，授权过期后未必能重新获取历史版本，应先恢复授权并检查节点结果。

控制台不会把兼容包自动拆成可视化站点/路由，也不会自动维护兼容包中的证书；需要修改时上传新的完整包。现有独立运行配置不会被控制台自动读取或捕获；首次接管之前必须先完成手动备份、打包和核对。

## 切换与故障处理

- `observe` 模式下发布、灰度、回滚、漂移恢复和证书续期下发会被拒绝。`legacy` 模式下普通站点发布、灰度、普通回滚、漂移采纳和证书续期下发仍会被拒绝；只有经过独立管理员复核的原生包发布或回退可下发。
- 切回 `managed` 后，显式发布成功前不会自动对齐；发布失败按现有热切换和自动回滚机制处理。独立配置的完整备份应由运维另行保管。
- 观察/兼容模式不会把任意本地路径上传到控制台。兼容版本的漂移仅显示文件路径和哈希，不显示内容；节点上版本目录应由新的 Agent 创建，以确保配置与脚本不会对其他用户开放读取。
