# 现有配置的观察接入与 Lua 兼容

当节点已经用独立配置运行，尤其是配置中包含原生 Lua 指令、第三方 Lua 库或本机静态目录时，先把节点加入控制台并不等于可以立即由控制台接管。使用节点组的“配置接管方式”保护现网：

| 模式 | 节点上线行为 | 控制台能力 | 适用场景 |
| --- | --- | --- | --- |
| 控制台托管 `managed` | 自动对齐节点组当前版本 | 预览、审批、发布和回滚 | 已完成迁移的站点 |
| 观察接入 `observe` | 不自动下发配置 | 上传分析、草稿、审计和漂移查看 | 先盘点现网，验证导入结果 |
| 兼容配置 `legacy` | 不自动下发配置 | 只读观察、导入分析和版本留痕 | 保留原生 Lua 及第三方依赖 |

## 推荐接入流程

1. 在控制台新建或选择节点组，先在“节点组设置 → 配置接管方式”选择“观察接入”或“兼容配置”。同一台服务器的多个实例应分别使用对应的节点组；实例档案仍负责根目录、端口、共享/独立数据面和标准版/国密版匹配。
2. 在节点上执行控制台生成的注册命令。首次注册已有独立配置时继续使用 `-replace-local-config`：Agent 会把当前配置打包到 `agent/backups/standalone-*.tar.gz`，但观察/兼容模式不会因为上线而覆盖它。
3. 在“配置导入”中上传完整配置展开结果、保留目录结构的 `tar.gz`，或一次选择主配置和它引用的多个文件。导入器只读取上传内容，不会让控制台通过 Agent 任意读取节点文件。
4. 先查看导入报告和重新校验结果。报告会列出未转换指令、缺失的 include、证书材料、站点路由以及 Lua 兼容清单；Lua 脚本和依赖只记录路径、大小和 SHA-256，不会被控制台执行。
5. 现网验证完成后，再把模式切回“控制台托管”。这一步只解除发布门禁，不会自动发布或自动对齐；请人工确认草稿、预览差异、完成片段审批，再显式发布。

## Lua 的边界

控制台托管的 Lua 仍然是 `docs/lua.md` 定义的受限路由脚本：脚本经过双人审批，写入不可变版本，并只能使用批准的运行时能力。`dofile`、任意第三方 `require`、文件读写、数据库直连和 `ngx.socket` 等旧配置依赖不会因为导入而自动获得权限。

导入报告检测到 `*_by_lua_file`、Lua 动态模块、`lua_package_path` 等内容时，会把节点标记为需要兼容处理，并列出上传包中发现的 Lua/依赖文件。需要长期保留完整原生运行时的节点应保持 `legacy`；需要迁移到控制台的功能，应逐条改写成受限 Lua 插入点并在测试节点上验证。

## 切换与故障处理

- `observe` 和 `legacy` 模式下，发布、审批下发、灰度、回滚、漂移恢复和证书续期下发都会被拒绝，防止误覆盖本地配置。
- 切回 `managed` 后，若发布失败，Agent 仍按现有热切换和自动回滚机制处理；原有独立配置的备份仍保留在 Agent 状态目录中。
- 观察/兼容模式不会把任意本地路径上传到控制台。漂移详情只展示 Agent 能安全上报的受管版本目录文件；原生配置包和第三方依赖应由运维人员按审计流程上传。
